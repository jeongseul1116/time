# 자동 조율 — 회의 일정 조율 프로토타입

구글 캘린더 위에서 동작하는 회의 일정 조율 도구의 인터랙티브 프로토타입입니다.
`index.html` 하나로 되어 있어 브라우저로 열면 바로 실행됩니다.

## 문제

여섯 명의 회의를 잡을 때 주최자가 보는 것은 여섯 명의 사정이 아니라 **여섯 명이 캘린더에 남긴 흔적**입니다.
화면에는 "업무 집중"이라는 네 글자만 있고, 그게 옮길 수 있는 블록인지 절대 못 건드리는 시간인지는 적혀 있지 않습니다.
그래서 주최자는 캘린더를 참고 자료로만 쓰고 결국 여섯 명에게 다시 물어봅니다.

이것이 문제인 이유는 **확인 노동이 한 사람에게 몰리기** 때문입니다.
답이 다 모일 때까지 시간을 못 잡고, 조율에 쓸 수 있는 이틀 대부분이 여기서 사라집니다.

그리고 이건 참여자 잘못이 아닙니다. 갑자기 미팅이 박히는 조직에서 자기 시간을 지킬 유일한 수단이
미리 뭐라도 걸어두는 것이라, 캘린더는 기록이 아니라 **방어막**이 됐습니다.
그래서 해법은 참여자의 태도가 아니라 기록과 확인의 방식에서 찾아야 했습니다.

## 질문을 바꾼 것

"이 시간에 일정이 있는가"가 아니라 **"그 일정을 옮길 수 있는가"**를 묻습니다.
이 기준으로 보면 캘린더의 시간은 이렇게 나뉩니다.

| | 뜻 | 판정 |
|---|---|---|
| 옮길 수 없음 | 몸이 다른 곳에 있어야 함 | 외근·고객 미팅·면접·계약, 3명 이상 회의, 대표 참석 |
| 옮길 수 있음 | 혼자 하는 작업 | 업무 집중, 정리·작성·점검류 |
| 물어봐야 앎 | 판단 불가 | 1:1, 내부 리뷰 |

기존 도구는 이 셋을 "일정이 있다 / 없다" 두 값으로만 처리합니다.
그 결과 **물어보면 옮길 수 있는 시간이 화면에서는 잡을 수 없는 시간처럼 보이고**,
주최자는 화면만 보고 그 시간을 후보에서 제외합니다.
회의가 미뤄지는 원인은 시간이 부족해서가 아니라, 잡을 수 있는 시간이 잡을 수 없는 시간처럼 보이기 때문이었습니다.

해법의 방향도 여기서 나왔습니다.
캘린더를 정확하게 만드는 것이 아니라, **캘린더가 실제와 달라도 회의는 잡히게** 만드는 것입니다.

## 흐름

```
일정 만들기 (만들기 버튼, 또는 빈 칸 클릭)
  ↓
참석자 추가        → 여기서 자동 조율로 넘어간다
  ↓
링크 붙여넣기      → AI가 참석자와 필수·선택을 근거와 함께 배분, 주최자가 수정
  ↓
가능한 일정 뽑기    → AI가 후보를 찾고 고르는 것까지 완료
  ↓
1·2순위 → 확정 초대 + 슬랙 리마인드
3·4순위 → 확정 대신 시간 확보 + 겹친 당사자에게만 조율 요청
  ↓
가능 → 확정 초대 / 불가능 → 다른 시간 / 무응답 → 주최자가 리마인드
```

### 순위

- **1순위** 전원 실제로 비어 있음
- **2순위** 필수 전원 가능 · 선택만 겹침
- **3순위** 옮길 수 있는 일정 1건과 겹침
- **4순위** 옮길 수 있는 일정 2건과 겹침
- **제외** 옮길 수 없는 일정과 겹침 · 전사 일정으로 막힌 날 · 점심시간 · 주말

후보에서 빠지는 날은 화면에서도 빠진 것처럼 보여야 합니다.
주말은 미니 캘린더 · 주간 그리드 · 월 보기에서 모두 빗금과 흐린 글자로 표시되고,
미니 캘린더 아래에 `주말은 회의를 잡지 않습니다`라고 한 줄 적어 둡니다.

같은 순위면 점심 직후(집중이 떨어지는 시간)를 뒤로 미룹니다.
고를 때의 기준은 **물어볼 사람이 가장 적은 시간**입니다.

### 회의실

시간이 정해지면 그 시간에 **쓸 수 있는 회의실**이 같이 나옵니다.
사람 수가 들어가는 방 중 가장 작은 방이 자동으로 잡히고, 주최자는 목록에서 바꿀 수 있습니다.
찬 방도 숨기지 않고 **어떤 일정이 쓰고 있는지**까지 보여줍니다.
정원이 모자란 방은 몇 명이 못 들어가는지 적습니다.
회의실은 자리를 잡은 뒤에도 캘린더 블록에서 바꿀 수 있습니다.

사이드바 **리소스**에서 회의실 5개를 각각 캘린더처럼 켜고 끌 수 있습니다.
켜면 그 방의 예약이 무채색 블록으로 그리드에 서고, `사람 일정 숨기기`를 켜면
사람 캘린더가 빠져 **회의실 일정만** 남습니다. 어느 방이 언제 비는지는 이 화면이 가장 빠릅니다.

### 확정이 아니라 확보

3·4순위에서는 초대장을 보내지 않습니다.
겹친 블록의 주인에게만 "이 일정을 옮길 수 있나요?"를 묻고,
나머지 참석자의 캘린더에는 **미정** 상태로 자리만 잡아둡니다.
초대장이 가면 나머지가 수락·거절을 판단해야 하는데,
그건 주최자가 없애려던 확인 노동을 다시 만드는 일입니다.

참여자가 낼 답은 **가능 / 불가능** 둘뿐입니다. 리마인드는 주최자가 누르는 행동입니다.
대표처럼 재조율이 어려운 참석자가 있는 회의에는 "놓치면 다시 잡기 어렵다"는 표시가 붙습니다.
직급 기반 긴급 표시는 인플레이션이 생기고 직급 낮은 사람의 시간부터 갈리는 부작용이 있어,
"빨리 하라"는 주장 대신 **사실 표시**로 바꿨습니다.

## 캘린더 재현

프로토타입의 배경이 되는 구글 캘린더도 실제로 동작합니다.

- 일 / 주 / 월 / 연도 / 일정 목록 / 4일 보기, 주말 표시 · 거절한 일정 표시 토글
- 구글 공식 색상 팔레트, 캘린더별 색 배정, 배경 밝기에 따른 자동 글자색
- 겹치는 일정 배치 (3개까지 분할, 그 이상은 계단식), 참석자 프로필
- 일정 상세 팝오버 — 화상회의 링크와 전화 참여, 회의실(층·정원), 참석자 응답(수락·거절·회신 대기), 알림, 참석 여부 응답
- 빈 칸 클릭으로 빠른 생성, 미니 캘린더, 일정 검색, 사용자 검색
- **만들기**는 사이드바에 일정 편집기를 엽니다 — 제목 · 시간 · 참석자 · 화상 회의 · 회의실 · 위치 · 설명.
  자동 조율은 별도 메뉴가 아니라 이 화면의 **참석자 추가** 자리에 있습니다.
  혼자 하는 일정이면 이 시간이 맞으니 그냥 저장하고, 사람이 붙는 순간부터 이 시간은 추측이 되기 때문입니다
- 주 이동 시 주마다 다른 일정 생성 (같은 주는 항상 같은 결과)

## 데모

- 우측 하단 **💡 처음 이용해봐요!** — 4개짜리 체크리스트입니다.
  항목을 누르면 실제 버튼이 눌리고, 어떤 버튼이 눌렸는지 표시가 따라붙습니다. 이미 한 항목도 다시 할 수 있습니다
- 슬랙 스레드 / 노션 문서를 최근 목록에서 고르면 링크 분석이 바로 돌아갑니다
- `Shift + D` — 캘린더가 꽉 찬 주 ↔ 여유 있는 주 전환 (조율 요청 분기를 보려면 꽉 찬 주)
- 보기 단축키 `D` `W` `M` `Y` `A` `X`, 오늘 `T`, 앞뒤 이동 `N` `P`
